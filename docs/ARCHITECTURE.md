# 实现架构

## 依赖方向

```text
Forge 游戏入口 / 指令 / 实体呈现 / GameTest
                    ↓
          Simulation 公共用例
                    ↓
  SimulationEngine + EventBus + LoopSystem
                    ↓
       领域规则 → WorldModel 数据契约
                    ↓
             WorldCodec / WorldStore
```

`core` 没有 Minecraft、Forge 或第三方库依赖。`forge` 依赖 `core`，打包时把核心类放入模组 JAR。新增领域规则通过 `LoopSystem` 和 `Definition` 注册，无需更改调度器。领域之间读取共同的数据契约、发布事件，不调用彼此的实现。

每个实例都依次执行感知、评估、决策、执行、反馈、演化。`DomainSystem` 复用批量对象的管线；没有反馈或跨代变化的实例保留空钩子，频率由定义控制。具体公式目前在各领域规则中，世界预算和投放时代通过 Forge 配置调整。

调度使用按到期时刻排列的优先队列，同一时刻按固定注册顺序运行。一次预算耗尽时保留未处理时间，不跳过日期；同一时刻的所有系统完成后才允许形成存档检查点。工作预算限制的是系统批次，不是严格毫秒预算；大人口下仍需要进一步把单批次分片。

随机数由世界种子、系统名、结算时间和实体 ID 混合派生，不依赖 JVM 全局随机序列。存档不用保存内部 PRNG 状态。气候在感知阶段复制区域快照，避免边更新边读取造成空间方向偏差。

## 数据与游戏世界

主世界有两条兼容路径：原版类型继续采用原有 24×12 区域抽象模拟和城邦投影；`adventurers:planet_small/medium/large` 则注册真正的 `PlanetChunkGenerator` 与 `PlanetBiomeSource`，由同一地理概览驱动区块、群系、文明选址和地图。下界、末地仍使用原版生成器。

`TerrainAtlas` 的旧算法 1 保留原有板块分区和 32 轮侵蚀。算法 2 由 `GeologicalHistory` 在 96×48 球面网格上重建 0..16 阶段：板块沿种子决定的三维轴旋转，反向采样搬运上一阶段地壳，边缘相向速度决定抬升；前期河网驱动本期侵蚀与下游沉积，风向水汽输送产生雨影。每阶段随后用优先洪泛构建无环汇流方向、累计汇水量和湖盆水位。采样时插值得到地表、局部切割河道，根据纬度、海拔和湿度选择群系。洞穴在球面三维坐标中采样；矿化读取板块资源。三个尺寸对应模拟区域边长 96/192/384 格，地理概览采样成 24×12 模拟区域，不随实际区块数量膨胀。

地理数组在构造后只读；最多 288 个文明选址结果独立缓存。生成器在创建结构状态或群系前绑定 `RandomState.seed()`，不读取服务器上正在演化的城邦对象。Minecraft 26.3 的 `buildTerrain`、`getBaseColumn` 和 `getBaseHeight` 共用方块规则，维护地表/海床高度图；后续植被、结构和普通生物由原版流程生成。`getOrigin` 为首次出生搜索提供干燥陆地。旧世界不会自动更换生成器或移动城邦。

地质历史按种子和 `TerrainSettings.version` 固定；区块线程只读末期帧，`WorldModel.observedTerrain()` 按持久时钟选择当前阶段。`GenesisGeology` 每 12 日先更新区域地貌/水文/矿化，保留当日生物量与基因；`Ecology` 和 `Evolution` 跳过同日地质变化，生态次日响应、特质筛选在两轮地质间进行。第 192 日后选址门槛开放。检查点完成同一时间戳的所有系统才保存，所以无需额外阶段字段或修改格式版本；重建历史和恢复时钟即可继续。物种尚不反馈到地质历史，投放后不重塑方块。

`PlanetPregenerator` 将出生地和文明足迹加入去重队列，按离中心由近到远排列、跨界坐标先归一化。每 tick 限制新启动数和并发数，使用独立、不持久化、不运行实体模拟的加载票据，请求 FULL 后异步轮询；只在 future 已完成时读取结果，不阻塞服务器线程等待。完成、失败、停服均释放票据。失败暂停模拟并显示原因；重启重建计划并复用区块文件。文明满足条件但预生成未完时不继续自动快进，等待全部足迹完成后开放投放。

`PlanetCoordinates` 对经度取模；过极点反射纬度并加半周经度，保持球面拓扑。`PlanetBoundary` 在服务器 tick 处理超出投影范围的根实体，加载目标区块并传送整组乘客，保留载具货物；越极点反转南北速度与朝向。只有星球主世界启用。边界传送不处理跨界视野、重力、原版装饰或玩家方块的镜像同步。

`PlanetAtlasMap` 使用一个共享、锁定的原版 `MapItemSavedData`，锁定防止原版地图采样覆盖星球投影。地形/河流、区域植被状态与城邦标记绘制到 128×64 地图带；日期或城邦数改变后更新。Minecraft 保存地图像素，自定义 `SavedData` 只索引地图 ID；重新领取或重建服务复用同一张图。新算法地图会切换地质阶段并绘制阶段进度条；这属于离散历史帧显示，尚无连续插值动画或独立界面，也不表示实际植物方块随抽象生物量生长。

文明是只保存统计与成员关系的数据容器。个人根据需求和能力选择活动，重复活动形成角色，再由人数与危机压力聚合出权力中心。当前政治实现仅记录影响权重，不宣称具有完整制度、外交或战争决策。

NPC 持久状态保存在核心中。距离多个玩家最近的区域决定热/温/冷等级，Minecraft 只给热区创建有限数量的村民外壳。外壳死亡会回传核心；外壳卸载不会被视作死亡。创建外壳前检查所在区块的实体区域已加载并运行，避免地形先到、实体区域后到时产生不可见副本；落点按碰撞体判断，允许草丛但拒绝头部阻挡。村民仍使用原版寻路/AI，这是完整四层 AI 和拼接实体完成之前的交互方式。

建筑复用部件模型，有六个资源消耗阶段。Forge 在已加载区域逐步放置部件，呈现记录防止重启后不断重建玩家修改的房屋。此实现不包括文化风格模板、拆除修复施工和一般建筑蓝图编辑器。

## 时间与持久化

24,000 tick 为一日，24 日为一年，6 日为一季。生成时默认每 5 个服务器 tick 快进一日，可用配置调整；加速同一个引擎，运行时服务器每 tick 推进一个模拟 tick。睡觉或 `/time set` 暂不改变模拟时钟。快进不移动 Minecraft 的天体或昼夜。

存档格式版本为 2，兼容读取版本 1。原子保存包括世界、区域、NPC、资源、建筑、政治权重、科技/魔法进展、玩家身份、符文知识、法术、任务和有限历史。版本 2 在原有负载后追加是否为星球、区域边长、地形算法版本；地理数组及新算法的完整阶段历史由种子和版本重建，动态生态数据与时钟从存档恢复。旧算法不被新算法替换；算法 2 星球不能降级交给只支持算法 1 的模组读取。旧存档按原版路径读取，写入时升级并保留原文件备份；旧版模组不能读取版本 2。

读取校验大小、CRC、ID 唯一性、引用关系及地理设置。Forge 启动时检查实际生成器与存档地理类型、种子和尺寸匹配；不支持的算法版本或配置冲突会拒绝启动，保留存档。不会反序列化任意 Java 对象，也不会自动覆盖损坏存档。

存档重载一致性通过完整字节比较验证；检查两条相同种子的演化路径以及保存/恢复后继续运行的结果。热区观察者与游戏实体属于运行时对象，不参与持久快照。
