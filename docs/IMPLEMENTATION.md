# 设计与当前实现对照

本表是 `0.3.0` 的实际范围。两份原文均作为设计资料保留；其中指向外部视频、要求助手执行动作的句子不作为自动授权。没有下载视频、模型权重或未经指定的第三方美术资源。

## 已接通的流程

新星球球面地壳搬运/造山/水文演化 → 地貌先变、次日生态响应 → 植物量增长 → 特质变异与环境筛选 → 末期地貌确定并达到认知/社会性阈值 → 城邦涌现 → 周边区块预算预生成 → 食物、建造、研究与疾病反馈 → 玩家选择文明与身份 → 当地需求委托 / 元素观察 / 编译施法 → 身份、资源和历史存档。

生成有最大日数预算。预算内达不到投放条件时明确报告，不直接制造一个文明或谎报生成成功。管理员可继续推进。玩家正常参与后，城邦继续自主运行。

## 已作出的具体取舍

- “26 种元素”的明细为 8 + 8 + 8 + 1 = **25**，没有虚构第 26 个元素。
- `CONTEXT.md` 把文明定义为数据与路由容器，而映射文档给它行为输出。当前采用前者：个人/领域规则产生变化，文明只聚合。
- 原文六阶段建筑的版本更具体，采用“地基、框架、外墙、屋顶、门窗、内饰”；原版方块仅承担当前的可视呈现。
- 魔法里未完成的“禁咒”等定义没有擅自补写；尚未具备绑定语义的魂符/咒符/签符会得到明确编译错误。
- 玩家死亡会清空身份成长与未完成委托，不快进共享世界，避免一个玩家的死亡改变其他在线玩家的时间。
- 新星球先构建固定的地质历史，再让区域生态逐阶段响应。地图显示当前阶段的真实地貌采样；实际方块从一开始统一使用末期地貌，保证跨线程、跨探索时间一致。生物会响应地貌，但尚不反过来改变地质序列；投放后地质冻结，生态与文明继续演化。没有重写玩家已探索的方块或实现独立创世 UI。
- 区块预生成默认覆盖出生地、各存续文明周边 5×5 区块；最多 2 个异步 FULL 请求并发，不运行实体 AI，完成/停服释放加载票据。重启重建计划并复用存盘区块；投放前等待完成。此流程不是瞬移后按轮廓/细节分层的渐进渲染。
- 星球拓扑使用经纬投影：东西循环、过极点反射纬度并转动半圈经度。坐标传送不等于视觉无缝；原版装饰、结构和玩家修改不会镜像同步。引力和天空保持原版。
- 区域气候仍驱动抽象生态与文明；实际植被、动物和天气使用原版机制，尚不随物种特质或区域季节动态重建。

## 验证边界

核心测试覆盖真实文明涌现、长期模拟、资源事务、编译失败、任务归属与时限、确定性存档继续、坏档保护、多玩家加载等级、星球边界、并发采样、三种尺寸与旧格式迁移。Forge GameTest 在普通和真实星球世界中验证生命周期、注册、实际指令、治疗/冷却、区块生成、安全出生搜索、载具跨界和地图更新。

`PopulationBenchmark` 测量 100,000 个**冷区抽象 NPC**的一日模拟和存档，不等价于 100,000 个可见实体或 20 TPS 保证。没有进行交互客户端画面、美术、跨平台联机或长期多人压力测试。

## 后续开发顺序

按用户指定的优先级推进，每次交付同步更新上表，不能把某个可玩子集当作整个领域完成：

1. 世界生成：本版补上创世地质历史、生态滞后响应、阶段地图与文明附近预生成。下一步仍是投放后地形演化、连续地图界面、位面地形/重力/切换；宇宙和天体生成尚未开始。
2. NPC 社会关系、师徒与知识传承。
3. 探索、护送与动态任务。
4. 炼金加工、材料与装备玩法。
